# jobreport — design

**Date:** 2026-06-01
**Status:** approved
**Replaces:** a host-local `report.sh` (bash)

## Purpose

A single Go binary that reproduces the gitlab-procs-exporter "top-N process" report
(CPU / peak-RSS / IO tables with full CI job metadata) and adds a **job-URL mode**:
given a GitLab job-log artifact URL, it parses the log for the job's identity, exact
execution window, result and crash details, then runs the same Prometheus report scoped
to that window/node.

The metric series (CPU/mem/IO) live only in Prometheus; the job.log does **not** contain
them. So URL mode uses the *parsed* data (window, node, job filter) to drive Prometheus
queries, and additionally renders a parsed-from-log analysis section.

## Runtime / deploy

- Runs anywhere with network access to a Prometheus and (for URL mode) the
  job-log artifact host. **Connection details are parameters, not constants:** the
  Prometheus endpoint is supplied via `-prom` / `$PROMETHEUS_URL` (default
  `http://localhost:9090`); no host, IP, or credential is baked into the binary.
- Stdlib only (`net/http`, `encoding/json`, `regexp`, `sort`) — cross-compiles
  trivially (`GOOS=linux GOARCH=amd64 CGO_ENABLED=0`) and avoids supply chain.
- Source lives in this repo at `cmd/jobreport/` under the
  `github.com/rachlenko/gitlab-procs-exporter` module; built via
  `make build-jobreport[-linux]`.

## CLI

Flag-based, with an environment-variable fallback per flag so the parameters can
come straight from the GitLab job environment (see `README.md`). Two modes:

- **Report:** `jobreport [-prom URL] [-proc all] [-node all] [-window 10m] [-top 5] [-job-id ID]`
  `-window` is optional and defaults to the last 10 minutes; `-job-id`
  (or `$CI_JOB_ID`) auto-resolves the runner node from `gitlab_process_info`.
- **URL:** `jobreport -url '<job.log-URL>'` (or a bare URL as the first argument);
  the window is derived automatically from the log.

## URL-mode data flow

1. **Fetch** the log (HTTP GET, 60 s timeout). Also parse the URL path
   `/<YYYY_MM_DD>/<JOB_ID>/<TRACE_ID>/job.log` as a fallback id source.
2. **Parse** (after ANSI strip `\x1b\[[0-9;]*[A-Za-z]`) into `JobInfo`:
   - *Identity:* JOB_ID, CI_JOB_NAME/slug, pipeline id, project, runner name + shard +
     system ID, executor type, pod name + namespace, concurrent slot.
   - *Window:* min/max of `section_(start|end):<epoch>:` → `[start,end]`; per-phase durations.
   - *Result:* `ERROR: Job failed: … exit code N` / `FAILURE` marker.
   - *Crash:* "force-killing DS processes", ``Core was generated by `…` ``, top backtrace
     frames, killed process names + pids.
   - *Artifacts:* core_dumps.zip / service-logs.zip / logs.zip download URLs.
3. **Node resolution (best-effort):** Prometheus query_range
   `gitlab_process_info{environ=~".*<JOB_ID>.*"}` over the window → distinct `node_ip`.
   Found → scope tables to it. Empty (e.g. k8s-executor jobs, which aren't scraped) →
   fall back to all-nodes for the window and print a note.
4. **Render:**
   - **Parsed-from-log section** — identity, window+duration (UTC), phase timings, result,
     crash summary, artifact links.
   - **Three Prometheus top-N tables** (CPU / peak-RSS / IO) — byte-identical box format to
     the bash version, scoped to resolved node + window, with `NO DATA` note when empty.

## Prometheus logic (port of the fixed bash)

- CPU: `topk(N, increase(cpu_seconds_total{F}[Ws]))`, value as cpu-seconds + `~pct%` (cpu/W).
- Memory: `topk(N, max_over_time(resident_memory_bytes{F}[Ws]))` → peak RSS MiB.
- IO: `topk(N, increase(io_read[Ws]) + increase(io_write[Ws]))` → total MiB.
- Metadata map: `query_range gitlab_process_info{F}` over window, deduped per `node_ip|pid`
  keeping the **richest cmdline** (a pid can have several series; the last often drops
  cmdline/environ).
- Extractors: `shard` (`builds/glrtr-XX/N/`), JOB_ID (cmdline) / CI_JOB_ID (environ),
  WORKER_ID, CI_JOB_NAME[_SLUG], CI_PIPELINE_ID, CI_COMMIT_REF_NAME, CI_PROJECT_NAME.
  `jobcol` = one-line "shard, JOB_ID=…, WORKER_ID=…, slug" descriptor; `firsttok` = safe
  basename fallback.

## Files (approach A — one module, organized by file)

- `main.go` — arg parsing, mode dispatch, output orchestration.
- `prom.go` — Prometheus client + topk/metadata/table builders.
- `logparse.go` — fetch + ANSI strip + parse → `JobInfo`.
- `meta.go` — environ/cmdline field extractors.
- `render.go` — box-table renderer + section printer.

## Error handling

- Expired presigned URL (HTTP 403) → message telling the user to regenerate the link.
- No section epochs in log → require explicit `-window`/positional.
- Network / Prometheus failure → clear stderr message, non-zero exit.
- Partial parse → render whatever was found; never panic on missing fields.
